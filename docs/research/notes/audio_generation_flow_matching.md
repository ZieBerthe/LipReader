# Audio generation for lip-video-to-speech with flow matching / diffusion, and the VLA analogy

Research notes, compiled 2026-11-12. Scope: the audio-generation side (generative target, generator, vocoder, VLA analogy, compute, MPS). Visual front-end choice is covered by other researchers.
Every item under "Cited Findings" was read from the linked page in this session. Items marked **[background knowledge, not verified this session]** come from my prior knowledge and should be checked before they are relied on.

---

## Q1. Generative target options: mel + vocoder vs codec/VAE latents vs discrete units vs waveform

### Takeaway
For a student project on GRID with a 16 GB Mac, the best quality-to-difficulty choice is **an 80/100-bin log-mel spectrogram generated by conditional flow matching, then a pretrained neural vocoder** (HiFi-GAN / BigVGAN-v2 / Vocos) in place of Griffin-Lim. This is what V2SFlow (lip-to-speech, ICASSP 2025) and Matcha-TTS do. Continuous codec latents (SLD-L2S, 2026) give the current state of the art on LRS3, but they add a codec dependency and were trained on hundreds of hours with an H100. Discrete HuBERT units are a strong *auxiliary/intermediate* target for intelligibility, not a good final target on their own.

### Cited Findings
- **Mel + vocoder in a flow-matching lip-to-speech system (V2SFlow, KAIST/Microsoft, arXiv 2411.19486, ICASSP 2025):** the rectified-flow decoder outputs an **80-bin mel spectrogram (hop 160, window 640, 16 kHz)**, and **HiFi-GAN** converts it to a waveform. Video is 25 fps and audio 16 kHz. — [V2SFlow HTML](https://arxiv.org/html/2411.19486v2)
- V2SFlow does not regress the mel straight from video. It first predicts decomposed attributes from frozen **AV-HuBERT Large** visual features: **content** = K-means-discretised HuBERT tokens (Conformer, cross-entropy, label smoothing 0.1), **pitch** = YAAPT F0 normalised per sentence and quantised with a VQ-VAE (cross-entropy), **speaker** = a GE2E embedding (cosine loss). The flow decoder is conditioned on these attributes. — [V2SFlow HTML](https://arxiv.org/html/2411.19486v2)
- **Continuous codec latents (SLD-L2S, arXiv 2602.11477, Feb 2026):** maps lip features straight into the continuous latent space of **X-Codec-hubert (16 kHz, pretrained on LibriSpeech)**, "avoiding intermediate mel-spectrograms and discrete SSL tokens". It uses reparameterised flow matching plus speech-language-model and semantic losses. — [SLD-L2S abstract](https://arxiv.org/abs/2602.11477); [SLD-L2S HTML](https://arxiv.org/html/2602.11477v1)
- SLD-L2S vs prior work on LRS3-TED (UTMOS / WER%): Ground truth 3.57 / 0.71; Intelligible (units, 1 NFE) 2.70 / 27.73; DiffV2S (1000 NFE) 3.07 / 35.81; LipVoicer (400 NFE) 2.45 / 20.62; NaturalL2S (1 NFE) 3.66 / 30.37; **V2SFlow (30 NFE) 3.69 / 27.55**; **SLD-L2S (10 NFE) 4.21 / 30.22**. Note that the generative methods raise naturalness (UTMOS) but **not WER**. LipVoicer, which uses ASR-classifier guidance, has the best WER. — [SLD-L2S HTML](https://arxiv.org/html/2602.11477v1)
- **Discrete units + mel (Intelligible L2S with Speech Units, Choi, Kim, Ro, Interspeech 2023):** predicts both a mel spectrogram and "quantized self-supervised speech representations" (speech units). A **multi-input vocoder** "produces clear waveforms from blurry, noisy mel-spectrograms by referring to the speech units". — [arXiv 2305.19603](https://arxiv.org/abs/2305.19603)
- Unit HiFi-GAN variants adapt HiFi-GAN "to enable direct waveform generation from SSL units". — search snippet via [RobustL2S](https://ar5iv.labs.arxiv.org/html/2307.01233) (snippet only, not fully read)
- **Codec latents for flow matching also appear in other speech tasks**, e.g. FlowMAC (CFM for low-bitrate audio coding, arXiv 2409.17635) and CodecFlow (CFM in codec latent space for bandwidth extension, arXiv 2603.02022). — [FlowMAC](https://arxiv.org/pdf/2409.17635); [CodecFlow](https://arxiv.org/pdf/2603.02022) (titles and abstract-level claims from search results only)
- The **Vocos** "encodec" variant (`charactr/vocos-encodec-24khz`, 7.9M params) decodes EnCodec tokens (8 codebooks x 200 frames, values 0..1023; bandwidths 1.5/3/6/12 kbps). This is a ready-made decoder if one generates EnCodec-compatible features. — [Vocos GitHub](https://github.com/gemelo-ai/vocos)

### Inferences
- **Ranking for this project (quality vs difficulty):**
  1. **Mel (80 or 100 bins) + pretrained vocoder.** Easiest, debuggable (spectrograms can be inspected), the vocoder is off-the-shelf, and flow matching fixes the over-smoothing that a regression loss produces. V2SFlow shows the design is state of the art-level on naturalness. *Recommended main path.*
  2. **Mel + auxiliary HuBERT-unit prediction head (multi-task).** Adds an intelligibility signal cheaply. The units can also serve as the decoder's conditioning, as in V2SFlow. GRID's tiny vocabulary (51 words) makes unit prediction easy.
  3. **Continuous codec/VAE latents (X-Codec, DAC, EnCodec, Mimi, Stable Audio VAE).** Higher ceiling (SLD-L2S), with a shorter sequence (lower frame rate) that is easier for the generator. But the latent normalisation and codec choice are fiddly, and a frozen codec must be run on MPS too. A good "stretch" experiment.
  4. **Discrete units + unit HiFi-GAN only.** Very intelligible but discards prosody and speaker identity unless F0/speaker are modelled separately, as V2SFlow does. A unit HiFi-GAN usually has to be trained or found for the matching HuBERT layer and K. Not flow matching, so it misses the user's interest.
  5. **Direct waveform diffusion (DiffWave / WaveGrad).** Much longer sequences (16k–24k samples/s vs ~100 frames/s) and slow sampling. Not advisable on 16 GB with MPS.
- GRID is single-sentence, fixed-grammar, studio-recorded, and has many utterances per speaker. Speaker-dependent mel generation is far easier than on LRS3, so a ~20M-parameter mel flow model should reach high naturalness. The intelligibility bottleneck will be the visual representation, not the audio generator.

### Gaps
- I found no paper that combines flow matching, GRID, and a pretrained vocoder with published GRID numbers. Both V2SFlow and SLD-L2S train and evaluate only on LRS3/LRS2.
- SLD-L2S does not state the X-Codec latent frame rate or dimension on the pages read.
- **[background knowledge, not verified this session]** Typical continuous latent rates: EnCodec 24 kHz = 75 Hz frames; DAC 44 kHz = 86 Hz; Mimi = 12.5 Hz; Stable Audio Open VAE ≈ 21.5 Hz at 44.1 kHz with 64-dim latents. Check before use.

## Q2. Flow-matching / diffusion speech generators to borrow from, and which handle frame-aligned conditioning

### Takeaway
**Matcha-TTS's decoder is the closest fit and the cheapest recipe.** It is a ~18M-parameter OT-CFM 1D U-Net (ResNet + transformer blocks) that maps an **aligned** conditioning sequence (`mu`, same length as the mel) plus noise to a mel in 2–10 Euler steps. Replace its text encoder and duration model with "upsampled visual features", which needs no alignment search. **V2SFlow's DiT-style decoder** (8 layers, d=512, adaLN-Zero timestep, CFG γ=2, 30 Euler steps) is the proven lip-to-speech variant. F5-TTS/E2-TTS/Voicebox are text-infilling designs (unaligned text and masked mel) and are overkill for GRID.

### Cited Findings
- **Matcha-TTS (Mehta et al., ICASSP 2024, arXiv 2309.03199):** acoustic model **18.2M params** (HiFi-GAN vocoder 13.9M). The decoder is a **1D U-Net** with residual conv blocks and Transformer blocks (snake-beta FF activations; 2 down blocks, 2 mid blocks, 2 up blocks; one Transformer layer per block, hidden 256, 2 heads, attention dim 64). Trained for **500k updates on 2x RTX 3090, batch 32, lr 1e-4**; peak training RAM **4.8 GiB at batch 32 with fp16**. OT-CFM **σ_min = 1e-4**. Vocoder: pretrained **HiFi-GAN LJ_V1** with a denoiser at strength 2.5e-4. — [Matcha-TTS HTML](https://arxiv.org/html/2309.03199v2)
- Matcha vs Grad-TTS on LJSpeech: MAT-10 (10 NFE) WER 2.09%, MOS 3.84, RTF 0.038; **MAT-4 WER 2.15%, MOS 3.77**; **MAT-2 WER 2.34%, MOS 3.65**; GRAD-10 (14.8M params, 7.8 GiB RAM) WER 3.44%, MOS 3.49; GRAD-4 MOS 3.20. Vocoded ground truth WER 1.97%. So OT-CFM keeps quality at 2–4 steps, where score-based diffusion degrades. — [Matcha-TTS HTML](https://arxiv.org/html/2309.03199v2)
- Matcha repo: CLI example uses `--steps 10`; ONNX export defaults `n_timesteps=5`. Training on custom data: edit filelists in `configs/data/*.yaml`, run `matcha-data-stats` to compute `mel_mean/mel_std`, then `python matcha/train.py experiment=...`. There is a `ljspeech_min_memory` config. The repo README has no MPS notes. — [Matcha-TTS GitHub](https://github.com/shivammehta25/Matcha-TTS)
- **V2SFlow decoder:** rectified flow with a **DiT-inspired Transformer backbone, adaLN-Zero timestep conditioning, 8 layers, hidden 512, 4 heads**. Conditions are **concatenated on the channel dimension and interpolated to match lengths** (frame-aligned conditioning, video 25 fps to mel 100 fps). **Logit-normal timestep sampling**; **30 Euler steps**. **CFG: conditions dropped with p=0.1 in training; best γ=2** (UTMOS 3.780 and WER 28.5 at γ=2, vs UTMOS 3.365 at γ=1). The decoder trained **400k steps, batch 384 s of audio, single GPU**; the attribute encoders trained 50k steps on 8 GPUs. — [V2SFlow HTML](https://arxiv.org/html/2411.19486v2)
- V2SFlow-V results on LRS3: UTMOS 3.780 (GT 3.519), WER 28.5% (GT 2.5%), SECS 0.664. Subjective naturalness MOS 4.60 vs GT 4.42, but intelligibility MOS 3.91 vs GT 4.88. — [V2SFlow HTML](https://arxiv.org/html/2411.19486v2)
- **SLD-L2S:** 12 "diffusion convolution blocks" (DiCB, 57.7M params; a DiT ablation is 57.8M); **10 NFE**; **150k iterations, batch 16, one H100, about 5 days**, AdamW lr 2e-4 with cosine decay; trained on LRS3 (~439 h). — [SLD-L2S HTML](https://arxiv.org/html/2602.11477v1)
- **F5-TTS:** uses Vocos (default) or BigVGAN. Its benchmark uses 16 NFE. **Sway Sampling**, an inference-time flow-step schedule, "greatly improves performance". The v1 base model was released 2025-03-12. Pretrained models are CC-BY-NC (Emilia data). There is a community MLX port. — [F5-TTS GitHub](https://github.com/SWivid/F5-TTS)
- **LTA-L2S (arXiv 2509.25670, Sep 2025):** Mandarin lip-to-speech with a **flow-matching F0 predictor** and a **flow-matching postnet for mel refinement**. — [LTA-L2S](https://arxiv.org/pdf/2509.25670) (from search result summary; not fully read)
- **Few-step / one-step variants (2025–2026):** MeanFlow-style average-velocity models reach 1–3 NFE in speech enhancement (MeanFlowSE, arXiv 2509.14858; COSE, arXiv 2509.15952) and target speaker extraction (MeanFlow-TSE, arXiv 2512.18572). — [MeanFlowSE](https://arxiv.org/pdf/2509.14858); [COSE](https://arxiv.org/html/2509.15952v2); [MeanFlow-TSE](https://arxiv.org/html/2512.18572v1)
- **X-Pred MeanFlow (arXiv 2609.12728, 11 Sep 2026):** a token-to-mel DiT decoder (CosyVoice2 25 Hz token vocabulary, frozen HiFi-GAN) at 2–3 NFE. Small = 16 layers, 159M params; Base = 22 layers, 341M. At 2 NFE, UTMOS improves from 2.910 to 3.189 (Small) vs a direct-u MeanFlow baseline. No multi-step FM baseline is reported. — [X-Pred MeanFlow](https://arxiv.org/html/2609.12728)
- **DiffV2S** (1000 NFE) and **LipVoicer** (400 NFE) are diffusion lip-to-speech baselines. They are much slower than flow-matching ones (V2SFlow 30, SLD-L2S 10) and score worse on UTMOS. — [SLD-L2S HTML](https://arxiv.org/html/2602.11477v1)

### Inferences
- **Concrete recipe ("Matcha decoder, video-conditioned"):** visual features (B, T_v=75, D) → linear to 80 channels (or a small Conformer) → interpolate ×4 to 300 frames (16 kHz/hop 160) or nearest/linear to the vocoder frame rate → `mu`. Then train the Matcha `CFM` decoder with loss ‖v_θ(x_t, t, mu) − (x1 − (1−σ_min)x0)‖² and sample with 4–10 Euler steps. Optionally add a prior loss ‖mu − mel‖ as Matcha does, so `mu` is a coarse mel; this also gives a free "regression baseline" to compare against.
- Use **CFG** (drop the conditioning with p≈0.1–0.2, sample with γ≈1.5–2.5), as V2SFlow found γ=2 best. Also consider **logit-normal t-sampling** (V2SFlow) or pi0's Beta schedule, which emphasise noisy timesteps.
- **Voicebox/E2/F5** solve *unaligned* text-to-mel via masked infilling with large models (≈300M+). Video is already time-aligned, so their main innovations are unnecessary. The parts worth borrowing are the DiT backbone with ConvNeXt blocks and sway sampling.
- Voice-conversion-style flow matching (content features aligned to frames, mel out) is structurally identical to this task. CosyVoice's flow-matching decoder (token → mel, conditioned on upsampled tokens + speaker embedding) is the industrial template for "aligned features → mel via CFM".
- Matcha's 500k steps are for LJSpeech text-to-speech with alignment learning. With aligned conditioning and GRID's simple domain, 50k–150k steps is likely enough (see Q5).

### Gaps
- **[background knowledge, not verified this session]** Grad-TTS (Popov 2021) uses a U-Net score decoder with a mel-aligned prior `mu`. CosyVoice (2024) uses a CFM U-Net/DiT decoder with CFG ≈0.7 and 10 steps. StableTTS (~10M params, DiT + CFM) and DiffWave/WaveGrad (waveform diffusion, 50–1000 steps → 6 with schedules) exist. Shortcut models (Frans et al., 2024) allow 1–4 steps. Numbers for these were not fetched.
- "From Faces to Voices" (CVPR 2025) and NaturalL2S are cited as related flow/1-step lip-to-speech work, but I did not read their details.

## Q3. Pretrained neural vocoders on Mac/MPS and their mel configs

### Takeaway
Pick **one vocoder first, then make the generator emit exactly its mel**. The safest MPS options are **HiFi-GAN V1 / universal (22.05 kHz, 80 mels, hop 256, fmax 8 kHz)** and **BigVGAN-v2 22 kHz/24 kHz** (pure conv, with the CUDA kernel off by default). Both have no STFT in the forward pass. **Vocos (24 kHz, 100 mels, hop 256, n_fft 1024)** is small and fast but ends in an iSTFT, which may need CPU fallback on MPS. F5-TTS uses the same Vocos mel. Fine-tuning the vocoder on GRID ground-truth (or generated) mels is cheap and usually helps.

### Cited Findings
- **HiFi-GAN V1 config:** `sampling_rate 22050, num_mels 80, n_fft 1024, hop_size 256, win_size 1024, fmin 0, fmax 8000`, upsample rates [8,8,2,2], segment_size 8192. — [HiFi-GAN config_v1.json](https://raw.githubusercontent.com/jik876/hifi-gan/master/config_v1.json)
- **BigVGAN-v2 checkpoints (NVIDIA):** `bigvgan_v2_22khz_80band_256x` (22 kHz, 80 mels, fmax 11025, 112M params); `bigvgan_v2_22khz_80band_fmax8k_256x` (fmax 8000, 112M); `bigvgan_v2_24khz_100band_256x` (24 kHz, 100 mels, fmax 12000, 112M); 44 kHz 128-band 256x (112M) and 512x (122M). All are trained for 5M steps on a large compilation of speech, sound, and music. Final v2 checkpoints date from Sept 2024. **`use_cuda_kernel` defaults to False**; the fused kernel needs nvcc/ninja, i.e. CUDA only. — [BigVGAN GitHub](https://github.com/NVIDIA/BigVGAN)
- **Vocos mel model (`charactr/vocos-mel-24khz`):** `sample_rate 24000, n_fft 1024, hop_length 256, n_mels 100, padding center`; ConvNeXt backbone dim 512, 8 layers; **ISTFTHead** (n_fft 1024, hop 256). 13.5M params, trained 1M iterations on LibriTTS. — [Vocos config.yaml](https://huggingface.co/charactr/vocos-mel-24khz/raw/main/config.yaml); [Vocos GitHub](https://github.com/gemelo-ai/vocos)
- Matcha-TTS uses a pretrained HiFi-GAN (LJ_V1) plus a denoiser, i.e. the 22.05 kHz/80-mel/hop-256 config. — [Matcha-TTS HTML](https://arxiv.org/html/2309.03199v2)
- V2SFlow trains on 16 kHz audio with an 80-mel, hop 160, window 640 HiFi-GAN. This gives exactly 100 mel frames/s = **4× the 25 fps video rate**. — [V2SFlow HTML](https://arxiv.org/html/2411.19486v2)

### Inferences
- **Frame-rate arithmetic for GRID 3 s clips (75 video frames):**
  - 16 kHz / hop 160 → 100 Hz → **300 mel frames, exact ×4 upsampling.** No public universal 16 kHz/hop-160 HiFi-GAN is confirmed here, so one would need to train or fine-tune one.
  - 22.05 kHz / hop 256 (HiFi-GAN, BigVGAN-22k) → 86.13 Hz → ~258 frames, ratio 3.445 (use linear interpolation).
  - 24 kHz / hop 256 (Vocos, BigVGAN-24k, F5-TTS) → 93.75 Hz → ~281 frames, ratio 3.75.
  - Non-integer ratios are fine with `F.interpolate(..., size=T_mel)`, which is what V2SFlow does.
- **Recommended default:** `bigvgan_v2_22khz_80band_fmax8k_256x` or HiFi-GAN universal, using the matching 22.05 kHz / 80 / 1024 / 256 / fmax 8000 mel. The generator mel must use the *same* mel function (librosa slaney mel + log-clamp as in HiFi-GAN's `meldataset.py`). Normalise to zero-mean/unit-std for flow matching with dataset stats (as Matcha does) and denormalise before the vocoder.
- BigVGAN at 112M params is heavier than HiFi-GAN V1 (13.9M) but runs fine for 3 s clips on a 16 GB Mac at inference.
- **Fine-tuning on GRID:** first verify "ground-truth mel → vocoder" quality on GRID (the upper bound). If there are artefacts (GRID audio is clean, so a universal vocoder should be OK), fine-tune a few thousand steps on GRID mels. A more robust option is fine-tuning on *generated* mels (teacher-forced), which corrects the generator's systematic errors. Standard practice from Tacotron2/HiFi-GAN; not verified for GRID specifically.
- **Griffin-Lim to neural vocoder is likely the single biggest audible improvement**, even before any flow matching. Swapping the vocoder on the existing pipeline is a sensible first step.

### Gaps
- **[background knowledge, not verified this session]** GRID audio is distributed at 50 kHz (and a 25 kHz version), so it must be resampled to the vocoder's rate.
- I did not confirm whether the HiFi-GAN "UNIVERSAL_V1" checkpoint has the same config as V1 (it is believed to, 22.05 kHz/80 mels).
- No measured MPS inference speed for any vocoder was found.

## Q4. The VLA analogy: pi0 / pi0.5 action expert → "speech expert" conditioned on visual tokens

### Takeaway
pi0 is a VLM plus a ~300M "action expert" that shares the transformer's self-attention, under a blockwise-causal mask. Noisy action chunks (H=50) are flow-matched with τ fused by an MLP and integrated in 10 Euler steps. The mapping to lip-to-speech is direct: **visual encoder tokens ↔ VLM prefix, mel/latent chunk ↔ action chunk, 10-step Euler ↔ 4–10-step CFM**. Mainstream video-to-speech systems (V2SFlow, SLD-L2S) already follow this "frozen pretrained visual encoder (AV-HuBERT) + flow-matching generator" recipe. I found **no paper that explicitly frames speech generation as a VLA analogy**.

### Cited Findings
- **pi0 architecture (arXiv 2410.24164):** a single transformer with "two sets of weights (also known as experts)". The VLM expert (PaliGemma, Gemma 2B) handles images and text; the **action expert (~300M, width 1024, MLP 4096)** handles robot state and noisy actions. "The weights interact only through the transformer's self-attention layers." Total 3.3B. — [pi0 HTML](https://arxiv.org/html/2410.24164v4)
- **Attention mask:** blockwise causal with three blocks: [images+language], [state], [noisy actions]. Bidirectional within a block, no attention to later blocks; action tokens attend fully to each other and to the prefix. The state has its own block so its KV can be cached across integration steps. — [pi0 HTML](https://arxiv.org/html/2410.24164v4)
- **Timestep conditioning:** each noisy action is embedded by an MLP that concatenates the projected action with sinusoidal φ(τ) and applies swish linear layers. Note that this is not adaLN. — [pi0 HTML](https://arxiv.org/html/2410.24164v4)
- **Chunks and sampling:** action chunk **H=50**; **10 forward-Euler steps (δ=0.1)** from Gaussian noise. Path A^τ = τA + (1−τ)ε, target u = A − ε; **τ ~ Beta((s−τ)/s; 1.5, 1), s=0.999**, which emphasises noisier timesteps. — [pi0 HTML](https://arxiv.org/html/2410.24164v4)
- **pi0.5 / Knowledge Insulation (arXiv 2505.23705):** the backbone is trained on discrete **FAST**-tokenised actions while the action expert learns continuous flow-matching outputs. The expert reads backbone KV through a **stop-gradient**, so FM gradients do not corrupt the VLM. Physical Intelligence notes that stop-gradient alone was not sufficient, hence the added FAST auxiliary loss. The goal is faster training and preserved VLM knowledge. — [Physical Intelligence KI page](https://www.pi.website/research/knowledge_insulation); detail on the sg() placement from a secondary review: [themoonlight review](https://www.themoonlight.io/review/knowledge-insulating-vision-language-action-models-train-fast-run-fast-generalize-better) (secondary; verify against arXiv)
- Generic description of current VLAs: a "VLM backbone for semantic grounding and a Diffusion Transformer (DiT) action expert for continuous action generation". — search results for [PAMAE arXiv 2606.27144](https://arxiv.org/pdf/2606.27144) / related VLA papers (snippet-level)
- Searches for an explicit VLA ↔ speech-generation analogy found only VLA papers that use audio as an *input* (e.g. HEAR, vision-sound-language-action, arXiv 2603.16086), not speech output. — [HEAR](https://arxiv.org/html/2603.16086)
- The closest audio analogue to "pretrained perception backbone + flow expert" is V2SFlow/SLD-L2S: **frozen AV-HuBERT Large** visual features (1024-dim from 88×88 grayscale mouth ROIs) feed a flow-matching generator. — [V2SFlow HTML](https://arxiv.org/html/2411.19486v2); [SLD-L2S HTML](https://arxiv.org/html/2602.11477v1)

### Inferences
- **Mapping table:**
  | pi0 | Lip-to-speech |
  |---|---|
  | PaliGemma VLM prefix tokens (images + text) | Visual encoder tokens: 75 frames × D (AV-HuBERT / their lip-reading encoder), optionally with predicted text/units |
  | Proprio state block | Speaker embedding / speaker ID token (constant across steps, so cacheable) |
  | Noisy action chunk, H=50 × 18-dim | Noisy mel chunk, e.g. 300 × 80 (or codec latents, ~75 × 64–128) |
  | τ-MLP fusion | Sinusoidal t → MLP, added or adaLN (V2SFlow uses adaLN-Zero) |
  | 10 Euler steps | 4–10 Euler steps (Matcha MAT-4 already good) |
  | Beta(1.5,1) τ schedule | Logit-normal (V2SFlow) or Beta, both emphasising mid/noisy t |
  | KI stop-gradient + FAST aux loss | Freeze or stop-grad the visual encoder; add an aux CE head on text/HuBERT units (the "FAST tokens" analogue) |
- **Two ways to condition the "speech expert":** (a) **pi0-style joint attention / cross-attention** from mel tokens to visual tokens, which needs no explicit alignment but must learn it; (b) **Matcha/V2SFlow-style frame-aligned additive/concat conditioning** (upsample 25→~100 Hz). With synchronous lip video, (b) is simpler, cheaper, and more data-efficient. (a) is the more literal VLA analogue and could be offered as an ablation, e.g. DiT blocks with self-attention over [visual tokens ; noisy mel tokens] under pi0's blockwise mask.
- The "chunk" concept matters less here: a 3 s GRID utterance (~300 mel frames) fits in one chunk. Chunking only matters for streaming or long utterances.
- The KI insight transfers: train the generator with gradients stopped into a pretrained lip encoder (or freeze it). Keep a discrete auxiliary objective (word/char CTC or HuBERT-unit CE) on the encoder, which is the role FAST plays.

### Gaps
- No primary source found that explicitly draws the VLA ↔ video-to-speech analogy. This may be a novelty point for the project report.
- The Octo / Diffusion Policy / GR00T designs were not fetched this session. **[background knowledge]** Diffusion Policy uses a 1D temporal conv U-Net with FiLM conditioning (close to Matcha's decoder); GR00T N1 uses a DiT flow-matching head that cross-attends to VLM tokens; Octo uses a small diffusion head on a readout token.

## Q5. Training cost for a ~10–50M conditional flow-matching mel generator, plus pitfalls

### Takeaway
Published references sit at **150k–500k steps on 1–2 datacenter GPUs**, but with much harder data (LJSpeech text alignment; LRS3 in the wild). For GRID with frame-aligned conditioning, a ~15–25M Matcha-style decoder at batch ~16–32 for **~50k–150k steps** is a reasonable plan. My rough estimate on an M5 MPS is **about 0.3–1 s/step**, i.e. roughly a day or more per 100k steps. This is unverified and should be benchmarked. The main pitfalls are over-smoothed mels from regression losses, mismatched mel configs, wrong normalisation, and the mistaken expectation that the generator fixes intelligibility.

### Cited Findings
- Matcha-TTS (18.2M): **500k updates, 2× RTX 3090, batch 32**, fp16 peak RAM 4.8 GiB. — [Matcha-TTS HTML](https://arxiv.org/html/2309.03199v2)
- V2SFlow decoder: **400k steps, batch 384 s of audio, 1 GPU**. — [V2SFlow HTML](https://arxiv.org/html/2411.19486v2)
- SLD-L2S (≈58M backbone): **150k iterations, batch 16, 1× H100, ~5 days**, on ~439 h of LRS3. — [SLD-L2S HTML](https://arxiv.org/html/2602.11477v1)
- **Multi-input vocoder motivation:** L2S mel predictors produce "blurry, noisy mel-spectrograms". — [Intelligible L2S, arXiv 2305.19603](https://arxiv.org/abs/2305.19603)
- **CFG matters:** without guidance (γ=1) V2SFlow's UTMOS drops from 3.78 to 3.37. — [V2SFlow HTML](https://arxiv.org/html/2411.19486v2)
- **Intelligibility gap remains even for SOTA generators:** WER 27–30% on LRS3 vs GT 0.7–2.5%. The generator improves naturalness, not content accuracy. — [SLD-L2S HTML](https://arxiv.org/html/2602.11477v1); [V2SFlow HTML](https://arxiv.org/html/2411.19486v2)
- Speaker-dependent GRID L2S is an established setting (e.g. LipSound2 with a 90:5:5 split on speakers S1–S4, reported with ESTOI/PESQ; Vid2Speech baseline ESTOI 0.335, PESQ 1.734). — [LipSound2, arXiv 2112.04748](https://arxiv.org/pdf/2112.04748) (from search snippet, not fully read)

### Inferences
- **Data volume:** 1,000 utterances × 3 s ≈ 50 min per speaker; all 33–34 speakers ≈ 28 h. This is a small but very homogeneous domain, which suits a ~20M model. Train multi-speaker with a speaker-ID embedding (cheap, and it improves voice consistency), then evaluate per speaker.
- **Rough compute estimate (my inference, unverified):** a 20M-param model on batch 32 × 300 frames ≈ 9.6k frame-tokens/step; FLOPs ≈ 6·N·tokens ≈ 1.2 TFLOP/step (convs add more). An M-series GPU in fp32 at realistic MPS utilisation plausibly gives ~0.3–1 s/step, so 100k steps ≈ 8–28 h. Memory is easily under 16 GB (Matcha needs 4.8 GiB at batch 32 in fp16 on CUDA). **Benchmark 200 steps before committing.**
- **Practical schedule:** precompute and cache visual features and mels to disk (do not run the visual encoder per step). Use AdamW lr 1e-4–2e-4, EMA of weights (common in FM/diffusion), and validate every ~5k steps by vocoding samples and running an ASR model (Whisper) on them to get WER.
- **Pitfalls:**
  1. *Regression over-smoothing:* L1/MSE mel regression gives a blurry, buzzy, metallic mel, worst with Griffin-Lim. Flow matching or CFG fixes the texture, and a neural vocoder hides the rest. Keep the regression `mu` as a prior/baseline, as Matcha does.
  2. *Mel mismatch:* the generator's mel must match the vocoder's mel exactly (sr, n_fft, hop, win, fmin/fmax, mel basis, log base, clamp). Test GT-mel → vocoder first.
  3. *Normalisation:* FM assumes N(0, I) noise, so normalise mels per bin or globally (Matcha's `mel_mean/std`). Unnormalised log-mels around −5 to −11 harm training.
  4. *Alignment / AV offset:* check AV sync. GRID is well aligned, but use the exact `T_mel` and interpolate the video features to it, rather than assuming an integer ratio.
  5. *Content hallucination with CFG:* high γ can produce fluent but wrong words. Monitor WER vs γ, not just naturalness.
  6. *Too-few-step sampling:* below ~4 steps quality drops unless using MeanFlow/shortcut/consistency distillation. Matcha shows 2 steps is still acceptable (MOS 3.65 vs 3.84 at 10).
  7. *Speaker leakage / overfitting:* with ~1k utterances per speaker, evaluate on held-out utterances. GRID sentences repeat word combinations, so use the standard splits to avoid sentence overlap.

### Gaps
- No published training curve for a Matcha-sized FM model on GRID, so the 50k–150k-step estimate is my extrapolation.
- No measured MPS throughput numbers for Matcha or similar models were found.

## Q6. PyTorch MPS compatibility notes

### Takeaway
Conv1d, ConvTranspose1d, attention (`scaled_dot_product_attention`), GroupNorm/LayerNorm, and snake activations run on MPS, so U-Net/DiT flow models and HiFi-GAN/BigVGAN (with the CUDA kernel off) should train and infer. **FFT-based ops (`torch.stft`/`istft`, `rfft`/`irfft`, complex dtypes) have historically been the weak spot.** Compute mels on the CPU in the dataloader (and cache them), and be ready to run Vocos's iSTFT head on the CPU or with `PYTORCH_ENABLE_MPS_FALLBACK=1`. Use float32; no float64 or complex128 on MPS.

### Cited Findings
- The MPS backend does **not support float64 or complex128** (Metal has no double type). — [PyTorch MPS notes](https://docs.pytorch.org/docs/main/mps.html) (via search snippet)
- Historical issues: `aten::_fft_r2c` raised NotImplementedError on MPS, with workaround `PYTORCH_ENABLE_MPS_FALLBACK=1` (CPU fallback, slower). In the MPS op-coverage tracker, users reported that the fallback sometimes did not work. Issue #126649 reported that `irfft(rfft(x))` was not identity on MPS. Issue #105665 noted ComplexFloat unsupported on MPS at the time. These are older issues; current status was not confirmed. — [MPS op tracker #77764](https://github.com/pytorch/pytorch/issues/77764); [#126649](https://github.com/pytorch/pytorch/issues/126649); [#105665](https://github.com/pytorch/pytorch/issues/105665)
- Community drop-in MPS STFT/iSTFT kernels exist (`mps-spectro`), and `mlx-spectro` claims 5–8× faster iSTFT than `torch.istft` on MPS (author's M4 Max benchmark, unverified). — [mps-spectro](https://awesome.ecosyste.ms/projects/github.com%2Fssmall256%2Fmps-spectro); [mlx-spectro PyPI](https://pypi.org/project/mlx-spectro/)
- BigVGAN's fused anti-aliased activation kernel is CUDA-only (nvcc/ninja) and **off by default** (`use_cuda_kernel=False`), so the pure-PyTorch path is used elsewhere. — [BigVGAN GitHub](https://github.com/NVIDIA/BigVGAN)
- The Vocos mel model ends in an **ISTFTHead** (n_fft 1024, hop 256), so it depends on iSTFT support. — [Vocos config.yaml](https://huggingface.co/charactr/vocos-mel-24khz/raw/main/config.yaml)
- F5-TTS has a community **MLX** implementation (Lucas Newman) for Apple Silicon. — [F5-TTS GitHub](https://github.com/SWivid/F5-TTS)
- The Vocos training stack pins PyTorch Lightning 1.8.6 (needs setuptools < 80); Matcha also uses Lightning and Hydra. Expect dependency friction on a recent PyTorch. — [Vocos GitHub](https://github.com/gemelo-ai/vocos); [Matcha-TTS GitHub](https://github.com/shivammehta25/Matcha-TTS)

### Inferences
- **Safe pattern:** (1) compute log-mels on the CPU with torchaudio/librosa once and save `.npy`; (2) train the FM model on MPS in fp32, trying bf16/fp16 autocast only if stable; (3) vocode with HiFi-GAN/BigVGAN on MPS, which has no FFT. For Vocos, move the ISTFT head's input to the CPU (`spec.cpu()`) or set `PYTORCH_ENABLE_MPS_FALLBACK=1`.
- Matcha's training uses Lightning `trainer.accelerator`, so set `accelerator=mps, devices=1`. Its Cython `monotonic_align` (MAS) is CPU-only but unnecessary when the text encoder and alignment are replaced by aligned video features.
- `torch.compile` on MPS is still limited. Run eager.

### Gaps
- I could not confirm from a primary source whether `torch.stft`/`torch.istft` are natively supported on MPS in the current PyTorch release (Nov 2026). Test on the student's install with a small script (`torch.istft(torch.stft(x.to('mps'), ..., return_complex=True), ...)` vs the CPU result).
- No source on ConvTranspose1d or snake-activation performance specifically on MPS. **[background knowledge]** These have been supported for several releases.
